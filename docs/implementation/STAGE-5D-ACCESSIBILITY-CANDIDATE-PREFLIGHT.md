## Facts, inference and separate unknowns

**Demonstrated by source:** model-backed query and typed directional cursor API; private retained widget paragraphs/preedit; actual endpoint-dependent draw versus IME computations; implemented Value/Text/Selection/action bodies; explicit null visible ranges; absent COM/property registrations; provider subclass installation/removal and event-raising bodies; bounded-but-dropping spike callback. These findings are scoped to the verified versions. Source code/comments advertising a capability are not counted as an implemented Windows method.

**Inference:** a future supported adapter would need coherent snapshots, stable identities/epochs, verified unit conversion, effective geometry and a truthful bounded completion/rejection protocol. A second independently shaped proxy or reuse of the IME rectangle would risk misrepresenting the actual widget. This is a requirement analysis, not a constructed workaround or proof that Rust + iced can never satisfy it.

**NOT VERIFIED here:** production UIA actions/events, native compositor/IME candidate placement and commit/cancel, Narrator speech, physical keyboard operation, high contrast, mixed-DPI/monitor changes, resource stress and complete provider lifetime behavior. Stage 2D human testimony belongs to its named isolated bridge; Stage 2G synthetic observations do not become real composition evidence. Stage 5A operator unavailability is not proof that no IME is installed. No existing gate or status is changed by this report.

## Smallest decision-changing prerequisite and owner boundary

There is **no truthful single-method fix** that would turn C0 into a source-preflight PASS: exposing a paragraph alone would leave the Windows methods absent, while adding LabeledBy alone would leave text authority and container scrolling absent.

The **single minimum prerequisite for reopening a passing-candidate decision** is one exact, published, source-auditable cooperating integration candidate that closes both boundaries: a supported coherent snapshot/actions contract for the actual rendered editor **and** implemented Windows label, container-scroll and required text/range contracts. Its complete source and artifact identities must demonstrate every required row, not merely propose attributes or getters. No such candidate was established in this bounded inspection. This prerequisite is an evidence condition, not an instruction or approval to implement, fork, download or prototype one. A partial upstream fix may justify another specifically requested source check, but cannot change the overall no-go while independent failures remain.

After a source-complete candidate is identified, the next decision still requires attributable owner scope/cost/acceptance authorization under [B01–B07](STAGE-5C-OWNER-DECISION-PACKET.md): exact versions/hashes and permitted paths, license/MSRV/transitive review, named maintainer/reviewer and willing operator, supported profiles, finite effort/run/resource limits, fixtures, stop/rollback conditions and explicit phase permissions. None is supplied or approved here. Only then could a separately authorized qualification task run; human/runtime gates on that candidate and the actual dashboard remain separate before production adoption/release. No fallback to native Windows controls, GUI replacement, shell change or automatic experiment follows from this failure.
