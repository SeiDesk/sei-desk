## Defects fixed

### P2: Invalid-config recovery copies could accumulate across restarts

`applications/preferences.rs` used PID-qualified recovery names. Repeated loads of identical malformed v1 bytes created redundant copies, exhausted 32 slots in one process and could create further sets in later processes. A new regression test loaded the same invalid file 40 times and **failed against the original implementation** when it became read-only.

Recovery now uses 32 fixed slots across process lifetimes, reuses a complete byte-identical existing copy, and creates distinct copies with `create_new`. It never overwrites an existing backup or the invalid original. At exhaustion it retains the original and reports read-only recovery. Existing legacy PID-named backups are preserved; this bounds new recovery files, without claiming legacy copies were deleted. Existing file-size bounds still apply.

Regression tests `repeated_invalid_startup_reuses_the_same_recoverable_copy` and `distinct_recovery_copies_have_a_lifetime_bound_without_overwrite` pass. They verify exact byte preservation, reuse over 40 loads, 32 distinct backups and rejection of a 33rd distinct recovery without mutation. The first test's red result and both green targeted runs are retained. Full persistence tests also pass, including atomic replacement, failed native replacement, stale-instance rejection, unsupported versions and interrupted temporary/lock files.

### P2: Clearing a search could hide the still-launchable selection

On the baseline release, searching `cm` selected CMake. Escape cleared the query and retained CMake by stable identity, but the results viewport stayed at the first catalog rows. The selected row was offscreen while its details and launch action still targeted CMake. Before captures reproduce this mismatch.

The dashboard now scrolls the results container to the reconciled selection after query edits, query clearing and accepted catalog-generation replacement. Status-only or stale frames do not repeatedly reposition it. Query edits do not issue a text-input focus operation, preserving the editor's existing caret; clearing retains the existing explicit focus behavior. Sort/group/view/pin behavior and identity-based launching remain intact.

Actual after captures show retained CMake visible after Escape, in grid view, and after catalog generation 1 → 2 refresh. This is the targeted event-wiring regression check; existing pure model tests alone could not prove widget-operation delivery. No new test merely counting internal tasks was added. Physical typing and edit-in-middle caret behavior were not operator-qualified in this stage.
